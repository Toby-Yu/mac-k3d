# Integration log

## Current priority: PF — platform foundation

**Nobody else uses this evaluation workflow until PF.7 passes.** PF makes Harbor the black box that runs every trial, pins the pipeline under test to the commit baked into each worker's `mac-k3d` binary, honors each task's declared resources, and proves two workers can share one controller.

Responsibility split to state to the mentor:

| Layer | Owner |
|---|---|
| Within one machine: which trial runs next, attempts, retries, timeouts, CPU/memory caps | Harbor (`-p`, `-i`, `-k`, `-n`, `-r`) |
| Across machines: which task subset goes to which worker | mac-k3d + Jenkins |
| Bare-machine prep, per-task inputs, iCode sanitize, integrity gate, report | mac-k3d |

Harbor has **no** contamination gate: `harbor job summarize` is a removed shim and `harbor analyze` is rubric-only. That is why P0.3–P0.6 stay on the mac-k3d side.

| Step | Proves | Status |
|---|---|---|
| PF.1 | One `harbor run` per build replaces the per-rollout loop | code + tests done; premise proven offline (row below) |
| PF.2 | Pipeline pinned to the commit baked into the worker binary (`mac-k3d pipeline --extract-to`, `BUILD.json`); one-command `scripts/redeploy.sh`; `eval --sync-pipeline` and the GitHub clone removed | code + tests done |
| PF.3 | Declared `cpus`/`memory_mb` honored; lock covers only its own node | code + tests done |
| PF.4 | `one_task` / `some_task` / `full_suite_task` per benchmark | code + tests done |
| PF.5 | Shards from many workers merge into one report | code + tests done |
| PF.6 | No dead scheduler or override-guessing code left | code + tests done |
| PF.7 | Two workers run shards of one suite at once | **pending (needs the second worker online)** |

PF.1–PF.6 are implemented and covered by fixtures. **PF.7 is the gate**, and it is the one thing on this branch that cannot be proven without machine time, so the workflow stays closed until it passes.

PF.7 needs, in order: (1) both workers online (`mac-k3d setup -c worker.yaml` on each, once); (2) `bash scripts/redeploy.sh --controller <controller> --worker <second worker> --start` from the checkout, which installs one build on the controller, the second worker and this PC, runs `start` on the controller (Helm installs `copyartifact`, `pipeline-utility-steps` and `hidden-parameter`, rewrites the nine jobs, deletes `eval_aggregate`) and `config -c worker.yaml` on each worker (node at **1 executor**), and ends with every host on the same `mac-k3d --version`. Later redeploys drop `--start`: `config` rewrites jobs only and does not install plugins. Without `copyartifact` the dispatcher's `Aggregate` stage fails at `copyArtifacts`; without `hidden-parameter`, `user`-profile builds fail on the unknown `hidden` parameter.
